00

Why evaluate — and what it actually is

A working demo isn't a shippable agent. Evaluation turns "it looked fine when I tried it" into evidence. You run the agent against a test dataset and let evaluators score every response. The evaluators behave like unit tests: most return a pass/fail per test case plus a short reason. From that you get a baseline, you can set a release gate (for example, "85% task adherence or we don't ship"), and you can compare two agent versions to see whether a prompt change helped or hurt.

Test dataset──▶ Your agent──▶ Response──▶ Evaluators (GPT judge)──▶ Pass / fail + reason
Status Model and dataset evaluation are GA; agent evaluation was public preview as of April 2026. The observability suite (evaluate, trace, monitor) reached GA in March 2026 and writes to Azure Monitor.
01

Prerequisites

  • A Microsoft Foundry project.
  • An agent in the project (we create one below).
  • An Azure OpenAI GPT deployment to act as the judge model for AI-assisted quality evaluators — e.g. gpt-4o-mini or gpt-4.1-mini. (Safety-only runs don't need it.)
  • The Foundry User role on the project (recently renamed from Azure AI User).
02

Create a simple agent

  1. Open the Foundry portal and select (or create) your project.
  2. Create an agent. Choose Create an agent / Build → Agents → New. A deployed model is usually pre-selected; if not, deploy one (e.g. gpt-4o-mini).
  3. Name it — e.g. KnowledgeTest — and write scoped instructions:
    instructions 
    You answer questions about the company invoice process.
Use only the connected knowledge; if the answer isn't there,
say you don't know. Be concise and cite the source.
  4. (Optional) Add knowledge — attach a File Search source or a Foundry IQ knowledge base so answers are grounded.
  5. Test in the playground with a couple of questions to confirm it responds. Now it's ready to evaluate.
03

The evaluation process, explained

Every evaluation answers one question: for each input, how good was the agent's output? There are three ways to supply the data, and three families of evaluators to score it.

Three ways to supply data

  • Queries only — you provide test questions; Foundry runs your agent to generate the responses at evaluation time, then scores them. This is the usual "test my agent" path.
  • Query + response pairs — you already captured outputs; Foundry just scores them.
  • Existing production traffic — point Foundry at data where it already lives (a Foundry response ID or an Application Insights trace) to score what actually happened.

Three families of evaluators

Most evaluators use a GPT model as a judge and return a score (or pass/fail) with a written reason.

FamilyExamplesAnswers…
AgentIntent resolution, Tool-call accuracy, Task adherence, Response completenessDid the agent do the right thing, the right way? (individual-turn scope)
QualityGroundedness, Relevance, Coherence, Fluency, SimilarityIs the answer correct, on-topic, and well-formed?
SafetyHate/unfairness, Violence, Self-harm, Protected materialIs the output safe? (individual-turn scope)

Offline vs continuous

  • Offline — run against a fixed test dataset before shipping; wire it into CI/CD as a release gate.
  • Continuous — sample live production traffic and score it on a schedule to catch drift.
Ground truth matters Evaluators like Groundedness or Relevance can judge without a reference, but if you want a correctness signal, include a ground_truth for each test case. A dataset with only queries and responses and no ground truth can score misleadingly high because there's nothing to be "wrong" against.
04

Include your user tests (author a dataset)

Your "user tests" are just a test dataset — one line per test case, in JSONL (or CSV). This is the part you own: the realistic questions your users actually ask.

Minimal — queries only

The service sends each query to your agent, captures the response, and scores it. Great for a first pass.

invoice-tests.jsonl 
{"query": "What is the maximum I can claim for meals per day?"}
{"query": "How long do I have to submit an expense claim?"}
{"query": "Who approves an invoice for 25,000 USD?"}

Stronger — add ground truth (and context)

Add the expected answer so correctness-based evaluators have something to compare against. Optionally add context (the grounding source).

invoice-tests-graded.jsonl 
{"query": "What is the maximum meal claim per day?",
 "ground_truth": "USD 75 per day."}
{"query": "How long to submit a claim?",
 "ground_truth": "Within 30 days of the expense."}
{"query": "Approver for 25,000 USD?",
 "ground_truth": "A vice-president (10,001-50,000 USD tier)."}

The same data as CSV (turn-level only) — handy if your team keeps cases in a spreadsheet:

invoice-tests.csv 
query,response,context,ground_truth
What is the max meal claim?,,Expense policy section 3,USD 75 per day.
How long to submit a claim?,,Expense policy section 3,Within 30 days.

Simulated user (multi-turn "user test")

To test a whole conversation instead of single turns, describe a scenario and let Foundry drive a simulated user against your agent. Each line needs an id, a test_case_description, and desired_num_turns.

sim-users.jsonl 
{"id": "case_1",
 "test_case_description": "An employee disputes a rejected meal claim and asks for the limit and the appeal steps.",
 "desired_num_turns": 4}
{"id": "case_2",
 "test_case_description": "A new joiner asks how to submit their first invoice and what fields are required.",
 "desired_num_turns": 3}

No dataset yet? Bootstrap one

  • Synthetic generation — Foundry generates query + ground_truth rows from your agent's instructions, an inline prompt, or an uploaded reference document. Best for prelaunch or low-traffic agents.
  • From traces — convert real production conversations into an evaluation dataset once you have live traffic.
Trainer tip Start with 10–20 realistic queries. That's enough to show where an agent struggles, and you reuse and grow the same dataset for every future version. Always validate your JSONL first: python -c "import json;[json.loads(l) for l in open('invoice-tests.jsonl')]"
05

Run the evaluation (portal)

  1. Open the Create wizard. Left nav → Evaluation → Create, or go to your agent → Evaluation tab → Create. Choose the Agent option and continue.
  2. Pick the data source. Select Existing dataset → Upload new dataset, name it (e.g. invoice-tests), and upload your JSONL/CSV. Or choose synthetic generation, or simulate conversations.
  3. Map the fields. Confirm the column mapping — required fields are marked with an asterisk. If you included ground truth, map {{item.ground_truth}} to Ground truth. Unassigned required fields cause that evaluator to fail.
  4. Choose evaluators. The portal preselects recommended ones; add what you need — e.g. Task Adherence, Tool Call Accuracy, Groundedness, Relevance, and the safety set. Pick the GPT judge deployment when prompted.
  5. Name the run and Submit. It takes a few minutes; status shows Running and updates when complete.
06

Read the results

  • Open Evaluation in the left pane and select your run. You'll see pass/fail counts per evaluator across the dataset.
  • Select the run name for row-level results: each row shows the query, the response, the ground truth, the evaluator score, and the reason for the score.
  • Compare versions. Select two or more runs and choose Compare for a side-by-side view; the comparison uses statistical t-testing so small differences are trustworthy.
Look for patterns, not single rows One failing row is noise. If groundedness fails consistently on one document type, that's a retrieval problem. If tool-call accuracy fails on a certain phrasing, that's a prompt problem. The per-row reasoning is what surfaces these patterns.

Evaluate from code (SDK) — for CI/CD

Once you want a repeatable release gate, drive the same evaluation from Python with the Azure AI Evaluation SDK.

bash 
pip install azure-ai-evaluation azure-ai-projects azure-identity

Score a dataset with evaluators

evaluate_local.py 
from azure.ai.evaluation import evaluate, RelevanceEvaluator, GroundednessEvaluator

judge = {"azure_endpoint": "...", "azure_deployment": "gpt-4o-mini"}

result = evaluate(
    data="invoice-tests-graded.jsonl",
    evaluators={
        "relevance":    RelevanceEvaluator(judge),
        "groundedness": GroundednessEvaluator(judge),
    },
    evaluator_config={"default": {"column_mapping": {
        "query":        "${data.query}",
        "ground_truth": "${data.ground_truth}",
        "response":     "${outputs.response}",
    }}},
    azure_ai_project=project,                # track results in Foundry
    output_path="./results.json",
)
print(result["metrics"])

Cloud run against your agent target

Upload your test dataset, then have Foundry send each query to your agent and score the generated responses.

evaluate_cloud.py 
dataset = project_client.datasets.upload_file(
    name="invoice-test-queries", version="1",
    file_path="./invoice-tests.jsonl",
)

run = client.evals.runs.create(
    eval_id=evaluation.id,
    data_source={
        "type": "azure_ai_target_completions",
        "source": {"type": "file_id", "id": dataset.id},
        "input_messages": {"type": "template", "template": [
            {"type": "message", "role": "user",
             "content": {"type": "input_text", "text": "{{item.query}}"}}]},
        "target": {"type": "azure_ai_agent", "name": "KnowledgeTest"},
    },
)
print("Run:", run.id)
Gate the pipeline Read a metric back and fail the build if it regresses, e.g. assert result["metrics"]["groundedness.gpt_groundedness"] >= 4.0. That turns evaluation into an automatic "don't ship" switch.

Troubleshooting

SymptomCause & fix
Everything scores ~100%No ground_truth in the dataset, so there's nothing to be wrong against. Add expected answers.
Evaluator shows "field unassigned" / failsA required field wasn't mapped. Assign it on the Field mapping page ({{item.ground_truth}} etc.).
Quality evaluators won't runNo Azure OpenAI GPT (judge) deployment connected. Add one; safety-only runs don't need it.
403 / can't create evaluationMissing Foundry User role on the project.
Agent evaluation option missingIt's public preview — ensure you're on the new Foundry portal and your project supports it.
JSONL rejectedMalformed lines. Validate with the one-liner in section 04 before uploading.
