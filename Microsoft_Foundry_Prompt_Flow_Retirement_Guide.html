Microsoft Foundry migration note

Is Workflow Support Being Stopped?

What is actually retiring, what replaces it, and what teams must do with existing Prompt Flow applications and deployments.

Verified: 20 August 2026
Contents 1. Short answer 2. Timeline 3. Existing flows 4. Alternative 5. Concept mapping 6. Migration plan 7. Deployment choices 8. What should I do? 9. FAQ 10. Official sources

1. Short answer

Yes—but it is specifically Prompt Flow that is retiring.
Microsoft will retire Prompt Flow in Microsoft Foundry and Azure Machine Learning on 20 April 2027. Microsoft is not stopping all workflow or orchestration capability in Foundry. The recommended replacement is Microsoft Agent Framework.
Terminology: A “flow” is a general executable AI workflow. Prompt Flow is the particular visual/YAML authoring product being retired. Agent Framework provides the replacement orchestration approach using Python or .NET code.

2. Confirmed retirement timeline

Now

No new builds

Prompt Flow is no longer recommended for new development.

Already

Images frozen

Prompt Flow runtime container images no longer receive security or package updates.

20 Apr 2027

Retirement

Foundry/AML web authoring, VS Code extensions, and related runtime images become unsupported and unavailable.

Risk to note: “Still running today” does not mean “safe to leave unchanged.” Frozen runtime images create security and dependency risks before the final retirement date.

3. What happens to existing flows?

QuestionAnswer
Will an existing flow stop immediately?Not immediately The retirement date is 20 April 2027. Use the remaining period for migration, but test current deployments and dependencies.
Will Microsoft automatically convert it?No announced auto-conversion Official guidance describes an audit, manual rebuild, validation, operational migration, and cutover.
Can the old visual canvas remain after retirement?No Microsoft states that the web authoring experience will no longer be supported or available after the date.
Will VS Code Prompt Flow tooling remain?No Related VS Code extensions are included in the retirement statement.
What about Prompt Flow runtime images?Retiring They already receive no security/package updates and become unavailable after retirement.
Does Microsoft promise that saved flow assets will be converted or retained?Not stated Do not assume conversion or post-retirement access. Export the flow definition, prompts, Python files, requirements, connections inventory, test data, and deployment configuration now.
Safe treatment for production flows: Keep the original flow operating only during a controlled parallel-migration window. Build the replacement beside it, compare outputs, move traffic, monitor, and then decommission the original resources.

4. Recommended alternative: Microsoft Agent Framework

Agent Framework replaces the visual, YAML-based Prompt Flow graph with a code-first Python or .NET workflow. It supports agents, tools, typed workflow steps, branches, fan-out/fan-in, multi-agent orchestration, and OpenTelemetry tracing.

Major learning change: Agent Framework does not provide a Prompt Flow-style visual graph editor. Teams that depend on drag-and-drop authoring must plan for code-based workflow development, source control, testing, and CI/CD.

6. Migration plan for an existing flow

  1. Inventory and export. Export flow.dag.yaml, prompt templates, Python tools, package versions, environment details, connection names, endpoints, test data, evaluation results, and traffic integrations.
  2. Map every node. Create a worksheet mapping each Prompt Flow node to an Agent Framework executor, agent, condition, fan-out, fan-in, or context provider. Account for all inputs and outputs.
  3. Rebuild a simple working path. Install agent-framework and agent-framework-foundry; implement the main linear route first, followed by branches and parallel paths.
  4. Use the correct client. For a Foundry project endpoint ending in .services.ai.azure.com, use FoundryChatClient. Do not use AzureOpenAIChatClient for that endpoint type.
  5. Validate side by side. Send the same representative inputs to old and new implementations. Microsoft’s guide proposes SimilarityEvaluator and a mean similarity target of at least 3.5/5 before continuing.
  6. Migrate operations. Add tracing, authentication, secrets management, error handling, scaling, alerts, evaluation gates, and CI/CD.
  7. Deploy the replacement. Choose Foundry Agent Service, Azure Container Apps, Azure Functions, or another appropriate container host.
  8. Cut over gradually. Move test traffic, then a controlled percentage of production traffic. Compare quality, latency, failures, and cost.
  9. Decommission only after stability. Once the new service is healthy and rollback is no longer needed, remove old endpoints, workspace connections, compute, and unused secrets.

8. What should your team do now?

Your situationRecommended action
Starting a new AI workflowDo not start with Prompt Flow. Use Microsoft Agent Framework or another supported orchestration approach that fits the use case.
Existing proof of conceptExport the assets and rebuild soon. It is an ideal low-risk migration exercise.
Existing production flowStart audit and parallel rebuild immediately; include security review because runtime images are frozen.
Training studentsExplain Prompt Flow as a legacy visual concept, but conduct new practical labs with Agent Framework, Git, tests, tracing, and deployment.
Visual authoring is mandatoryRecord this as a product-gap/requirement. Agent Framework is code-first and has no equivalent visual graph editor.

Minimum backup checklist

  • flow.dag.yaml and all source files
  • Prompt templates and variants
  • Requirements/package lock and runtime version
  • Connection inventory (names and targets—not plaintext secrets)
  • Environment variables and deployment settings
  • Representative input/output test set
  • Evaluation results and acceptance thresholds
  • Endpoint consumers, owners, SLAs, alerts, and rollback procedure

9. Frequently asked questions

Is Foundry Agent Service itself being stopped?

No. The cited announcement concerns Prompt Flow in Microsoft Foundry and Azure Machine Learning, not the whole Foundry platform or Agent Service.

Can I wait until April 2027?

That is high risk. A migration includes code reconstruction, output-parity testing, security work, deployment, traffic cutover, and rollback time. Runtime images are already not receiving updates.

Will my YAML import directly into Agent Framework?

Microsoft’s documented process is to export and map the YAML, then rebuild with WorkflowBuilder and executors. Do not plan around automatic one-click conversion.

Can I continue to use the open-source Prompt Flow project?

The Microsoft-hosted Foundry/AML experience, related extensions, and container images are explicitly retiring. The referenced page notes that an open-source project exists, but that does not extend Microsoft’s stated support for the retiring hosted experiences. For enterprise planning, follow the supported migration path.
