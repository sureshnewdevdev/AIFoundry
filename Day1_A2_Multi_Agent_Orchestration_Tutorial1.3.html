1. Learning Overview

Orchestration controls which component runs next, what data it receives, what state is preserved and when the workflow must stop or ask a human.

Identify nodes, edges, conditions and terminal states.
Separate durable workflow state from chat memory.
Differentiate handoff, direct message and broadcast.
Design retries with limits and explicit exit reasons.

Core vocabulary

ConceptPlain-language meaningFinancial example
Node / executorA unit that performs one step.Extract settlement fields
EdgeA permitted route from one step to another.Extraction → Matching
Conditional edgeA route chosen from runtime data.Variance ≤ 5% → Matched
StateWorkflow data shared or persisted across steps.Settlement ID, attempt, variance

HandoffTransfer of responsibility/control to another agent.Matching agent hands exception to Validation
Exit conditionA rule that deliberately ends a loop or workflow.Matched, human review, timeout
Trainer rule: If code already knows the next step, use a workflow edge. If a model truly needs to choose the next specialist, use agent-driven routing—but validate the handoff.

Offline Python queue demonstration

async_handoffs.py
import asyncio

async def ingestion_agent(source, extracted_queue):
    while True:
        event = await source.get()
        if event is None:
            await extracted_queue.put(None)
            return
        message = {
            "type": "FILE_READY",
            "correlation_id": event["settlement_id"],
            "payload": event,
        }
        await extracted_queue.put(message)

async def extraction_agent(inbox, matching_queue):
    while True:
        message = await inbox.get()
        if message is None:
            await matching_queue.put(None)
            return
        settlement = extract_fields(message["payload"])
        await matching_queue.put({
            "type": "MATCH_REQUEST",
            "correlation_id": message["correlation_id"],
            "payload": settlement,
        })

async def main():
    source, extracted, matching = asyncio.Queue(), asyncio.Queue(), asyncio.Queue()
    tasks = [
        asyncio.create_task(ingestion_agent(source, extracted)),
        asyncio.create_task(extraction_agent(extracted, matching)),
    ]
    await source.put({"settlement_id": "SET-1001", "file": "settlement.csv"})
    await source.put(None)
    await asyncio.gather(*tasks)

asyncio.run(main())
Production requirement: asyncio.Queue is only an in-process teaching aid. A production solution needs durable messaging, visibility timeouts/locks, delivery-count limits, dead-letter handling, authentication and monitoring.

Safe retry implementation

bounded_match.py
import asyncio

async def match_with_guardrails(state, max_attempts=3):
    seen_requests = set()

    while state["attempt"] < max_attempts:
        state["attempt"] += 1
        request_key = (state["settlement_id"], state.get("erp_sku"))

        if request_key in seen_requests and not state.get("new_evidence"):
            return exit_workflow(state, "HUMAN_REVIEW", "NO_PROGRESS")
        seen_requests.add(request_key)

        try:
            invoice = await asyncio.wait_for(
                get_erp_invoice(state["erp_sku"]), timeout=10
            )
            variance_pct = calculate_variance(state, invoice)
            if variance_pct <= 5:
                return exit_workflow(state, "MATCHED", "MATCH_WITHIN_THRESHOLD")
            return exit_workflow(state, "HUMAN_REVIEW", "VARIANCE_EXCEEDED")

        except TemporaryErpError:
            if state["attempt"] == max_attempts:
                return exit_workflow(state, "HUMAN_REVIEW", "MAX_ATTEMPTS")
            await asyncio.sleep(2 ** (state["attempt"] - 1))
        except MissingSkuError:
            return exit_workflow(state, "HUMAN_REVIEW", "MISSING_SKU")
Never use: while True with no timeout, attempt limit, progress test or escalation. A model saying “try again” is not a sufficient retry policy.

How the three topics work together

  1. State graph defines legal nodes and transitions.
  2. Persistent state/checkpoints preserve completed work and pending messages.
  3. Handoffs/messages move validated contracts between specialized agents.
  4. Loop guards bound uncertain matching work.
  5. Exit conditions always end in an explicit business status.
Target audit question: For any settlement, you should be able to answer: Where is it now? What has completed? Which message caused the transition? How many attempts occurred? Why did it stop?

13. Interview Questions and Answers

1. What is state graph orchestration?

It models work as nodes connected by edges, with conditions selecting runtime branches and state carrying controlled data through the workflow.

2. State versus checkpoint?

State is the current workflow data. A checkpoint is a durable snapshot of state and execution information used to resume later.

3. Why are typed messages important?

They make contracts testable, reject malformed data early and reduce ambiguity between agents.

4. What is an agent handoff?

A transfer of active responsibility or control from one agent to another, with a validated task and context.

5. Handoff versus direct message?

A direct message transfers information. A handoff also transfers ownership of the next action.

6. Why use asynchronous messaging?

It decouples producers and consumers, supports independent scaling and lets slow or unavailable downstream services recover without blocking the sender.

7. What is idempotency?

Repeating the same operation produces no additional side effect. It is essential when messages may be delivered more than once.

8. What is a dead-letter queue?

A destination for messages that cannot be processed after allowed attempts, preserving them for inspection and recovery.

9. What are loop guardrails?

Attempt limits, deadlines, cost/token budgets, repeated-action detection, progress checks, backoff and explicit escalation.

10. Transient versus permanent error?

A transient error may succeed later, such as HTTP 503. A permanent/business error needs correction or review, such as a missing SKU mapping.

11. Why store an exit reason?

It makes the outcome explainable, measurable and routable without parsing free-form model text.

12. What is optimistic concurrency?

An update succeeds only if the state version is still the version read, preventing silent overwrites by concurrent workers.

13. How do checkpoints help financial workflows?

They preserve progress during long runs or approval waits and avoid redoing completed steps after failure.

14. How do conditional edges help?

They route messages based on structured runtime data, such as variance, retry count or validation status.

15. What should a HITL package contain?

Identifiers, values compared, rule result, evidence, attempt history, tool errors, recommended action and correlation ID.
