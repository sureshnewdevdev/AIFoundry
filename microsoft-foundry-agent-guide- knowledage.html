00Overview & concepts

Microsoft Foundry is Microsoft's platform for building, grounding, and governing AI apps and agents. It was previously called Azure AI Foundry and was renamed at Ignite in November 2025 — the portal and docs now say "Microsoft Foundry," but you'll still see the old name in older tutorials and some URLs.

An agent is simply a model + instructions + tools. Unlike a plain chatbot that only generates text, an agent can call tools, retrieve from a knowledge base, and take actions to fulfil a request. You define it once, and the Agent Service keeps its behaviour consistent across conversations.

Two ways to build

  • Prompt agents (portal-first): create and configure an agent interactively in the portal, test it in the playground, then call it from your app. Best for getting started, internal tools, and most production agents that don't need custom orchestration.
  • Hosted agents (code-first): write the agent with a framework (Microsoft Agent Framework, LangGraph, OpenAI Agents SDK, Anthropic Agent SDK, or your own code) and deploy it to a managed runtime with its own identity and endpoint.
Version note — two API generations The classic Assistants-based API is being retired (the underlying Assistants API retires 26 Aug 2026; the classic agent service retirement is announced for 31 Mar 2027). The current SDK is azure-ai-projects 2.x and is not compatible with 1.x samples that use threads/runs/agent GUIDs. Always check imports before copying older code, and prefer the current official quickstart.

The full agent lifecycle in Foundry is: Create → Test → Trace → Evaluate → Optimize → Publish → Monitor. This handout walks the first six.

01Prerequisites

  • An Azure subscription with quota for a chat model in your region.
  • A Microsoft Foundry project (the portal can create one for you during the agent flow).
  • A deployed chat-capable model — e.g. gpt-4o-mini gpt-5-mini gpt-5.4-mini. Foundry's catalogue also includes Anthropic, Meta, Google, and other providers.
  • The Foundry User role on the project (needed to create/edit agents in the portal or SDK).
RBAC roles were renamed Foundry User / Owner / Account Owner / Project Manager were previously Azure AI User / Owner / Account Owner / Project Manager. The role IDs and permissions are unchanged — you may still see the old names in some places while the rename rolls out. A missing Foundry User role is the usual cause of "permission denied" when creating agents.
Use the new portal Make sure the New Foundry toggle is on. If you don't see Build, Operate, and Admin in the navigation, switch to the new experience — screens and menu locations differ from the classic portal.

02Create a simple agent (portal)

  1. Open the Foundry portal and sign in. If you're inside a project, click Microsoft Foundry in the top-left breadcrumb to return Home.
  2. Start the agent flow. Choose Create an agent (or Start building → Create agent). If you don't have a project yet, enter a project name and select Create; wait for the account and project to provision.
  3. Land in the agent playground. A deployed model is usually pre-selected. If prompted, deploy one (e.g. gpt-4o-mini) with a couple of clicks.
  4. Name the agent — for a class demo, something like expense-agent or it-support-agent.
  5. Write the instructions (the system prompt). Be specific about scope and refusal behaviour, for example:
    instructions.txt 
    You are an IT support assistant for Contoso.
Answer only from the attached policy documents.
If the answer isn't in the documents, say you don't know
and suggest opening a ticket. Keep replies short and cite the source.
  6. Chat to test. Send a prompt in the playground and confirm the agent responds. At this point the agent works, but it only knows what the model already knows — next we give it your data.

03Add knowledge (grounding)

Grounding lets the agent answer from your documents instead of only its training data, using Retrieval-Augmented Generation (RAG). Foundry gives you two levels: a quick File Search for a document or two, and enterprise-grade Foundry IQ for real data estates.

Option A — File Search (simplest, great for class demos)

  1. In the agent playground, open the Knowledge section and choose to add a knowledge source.
  2. Select Files and upload a PDF or Word document (e.g. an expense policy). Foundry chunks, embeds, and indexes it for you.
  3. Save, then ask a grounded question — e.g. "What's the maximum I can claim for meals?" The reply should come straight from the uploaded document.
Why start here No Azure AI Search service, no extra provisioning — one upload and you have a working RAG demo. Perfect for the first 20 minutes of a lab.

Option B — Foundry IQ (enterprise knowledge layer)

Foundry IQ is a dedicated knowledge layer built on Azure AI Search agentic retrieval. Instead of hand-building a RAG pipeline per source, you create a knowledge base that unifies many sources behind one retrieval endpoint. It plans the query, searches, reranks, and returns a cited, permission-aware answer. One knowledge base can be shared by many agents.

  • Sources: Azure Blob Storage, SharePoint, OneLake, Azure SQL, File Search, public web (Web IQ), and MCP servers.
  • Connection: the knowledge base exposes an MCP endpoint; you attach it to an agent directly or via a Toolbox (a curated set of tools behind one endpoint).
  • Retrieval quality: agentic retrieval breaks complex questions into sub-queries, runs parallel searches, and aggregates — with citations back to source documents.
  1. In Azure AI Search, enable a system-assigned managed identity and role-based access; create a knowledge base with one or more knowledge sources.
  2. In your Foundry project, deploy a chat model the knowledge base can use to synthesise answers (e.g. gpt-5.4-mini).
  3. Create a project connection to the knowledge base (managed-identity auth recommended).
  4. Add the knowledge base to the agent as an MCP tool / Toolbox, so it can call knowledge_base_retrieve.
  5. Grant the agent's managed identity the Search Index Data Reader role on the search service, then test with a grounded question.
Common 403s Grounding failures are almost always permissions: the search service identity needs access to the model, and the agent identity needs Search Index Data Reader on the search service. Use the 2026-05-01-preview API version for the knowledge-base MCP endpoint.

04Other tools & options

Beyond knowledge, an agent's power comes from the tools you attach in the playground:

  • Web search / Web IQ — live grounding on public web data with source attribution.
  • Code Interpreter — the agent writes and runs its own Python to compute, parse files, or make charts.
  • Functions & MCP tools — call your own APIs, remote MCP servers (from the Add Tools catalogue), or custom MCP servers hosted on Azure Functions.
  • Memory (preview) — persist context across sessions so the agent remembers earlier conversations.
  • Toolbox — define a set of tools once, version it, and expose it to any MCP-compatible agent through a single endpoint.
Teaching point "Knowledge" answers what does my data say?; "tools" answer what action can the agent take? Most useful agents combine both — e.g. retrieve a policy (knowledge) then file a ticket (function tool).

05Test in the playground

  1. Chat multi-turn. The playground keeps conversation history, so follow-ups like "tell me more about that" resolve against context. Use New chat to clear history and test cold starts.
  2. Inspect the run. Open Thread logs in an active thread to see each step — model calls, tool invocations, and retrieved chunks — so you can see why the agent answered as it did.
  3. Exercise tools. MCP and function tools can be validated directly in the playground before you publish, confirming connectivity, permissions, and behaviour.
Rate limits If the agent stops responding, you've likely hit a model quota/rate limit — wait a few seconds and retry, or deploy the model in a region with more quota.

06Evaluation & observability

Foundry's observability rests on four continuous activities: Trace (what happened in a run), Evaluate (is it good?), Monitor (how is it behaving over time?), and Optimize (make it better). Evaluations, monitoring, and tracing reached general availability in March 2026 and publish directly into Azure Monitor / Application Insights.

Quick evals in the playground

  1. Evaluations in the agents playground are on by default for Foundry projects (billed by consumption).
  2. Open Thread logs → Metrics and select the metrics you care about, then chat with the agent.
  3. Review the scores next to the thread. Playground results are kept for ~24 hours before expiring.

Built-in evaluators

CategoryEvaluators (examples)Answers…
QualityCoherence, FluencyIs the writing clear and well-formed?
RAGGroundedness, RelevanceIs the answer supported by retrieved sources?
SafetyHate/unfairness, Violence, Protected materialIs the output safe and compliant?
AgentIntent resolution, Tool-call accuracy, Task adherence/completion, Response completenessDid the agent do the right thing, the right way?

You can also write custom evaluators for domain-specific rules, and use the Agent Optimizer to automatically improve a hosted agent's instructions based on evaluation results.

Offline vs continuous

  • Offline (pre-deployment gate): build a test dataset, run evaluators, review scores, and only ship if thresholds pass. Ideal to wire into CI/CD so a bad build fails promotion.
  • Continuous: sample live production traffic (a modest 5–10% is a practical start) and score it in near-real-time — groundedness, task adherence, tool-call accuracy, safety — writing results next to your traces.
Permission for continuous evaluation The project's managed identity must have the Foundry User role on the Foundry resource, or continuous-evaluation rules silently do nothing. Assign it in the Azure portal under Access control (IAM).
Where to watch it The Agent Monitoring Dashboard in the portal shows token usage, latency, success rates, and evaluation trends. Because everything lands in Azure Monitor, you can also set alerts (e.g. page someone when groundedness drops below a threshold).

07Code-first (Python)

The same agent can be created from code with azure-ai-projects 2.x. Install, sign in, then point the client at your project endpoint. Treat this as a shape to adapt — confirm the exact current calls against the official quickstart, since the 2.x API differs from older 1.x samples.

setup.sh 
pip install azure-ai-projects azure-identity
az login                      # authenticate to your subscription
create_agent.py — illustrative 
import os
from azure.ai.projects import AIProjectClient
from azure.identity import DefaultAzureCredential

# Project endpoint: Foundry portal → project → Overview
with (
    DefaultAzureCredential() as credential,
    AIProjectClient(
        endpoint=os.environ["FOUNDRY_PROJECT_ENDPOINT"],
        credential=credential,
    ) as project,
):
    agent = project.agents.create_version(
        agent_name="it-support-agent",
        model=os.environ["MODEL_DEPLOYMENT_NAME"],   # e.g. gpt-4o-mini
        instructions=(
            "You are an IT support assistant. "
            "Answer only from the connected knowledge base and cite sources."
        ),
        # tools=[ ... attach File Search / MCP knowledge-base tool here ... ]
    )
    print("Created:", agent.name)
Endpoints you'll need The project endpoint comes from the project's Overview page; the model deployment name from Build → Deployments.

08Suggested classroom lab flow (~60 min)

  1. 0–10 min — Provision. Everyone creates a project and confirms a model deployment + Foundry User role.
  2. 10–25 min — Build. Create the agent, write scoped instructions, chat once to confirm it works.
  3. 25–40 min — Ground. Upload a policy PDF via File Search; ask a question that only the document can answer; open Thread logs to show the retrieved chunk.
  4. 40–52 min — Evaluate. Turn on Groundedness + Relevance metrics, ask one in-scope and one out-of-scope question, and compare scores.
  5. 52–60 min — Discuss. Where would Foundry IQ replace File Search? What thresholds would you gate a release on? Preview continuous evaluation.
Stretch goal Have a fast group swap File Search for a Foundry IQ knowledge base and add a second data source, then re-run the same evaluation to see whether groundedness improves.
