Ingestion validations

  • Hash the original file to detect duplicates and changes.
  • Preserve document ID, page, section and clause numbers.
  • Extract tables without losing row/column meaning.
  • Store version and effective dates separately from the text.
  • Carry access-control identities or groups into every chunk.
  • Quarantine malformed, encrypted or suspicious files.
Microsoft service option: Azure Content Understanding can transform unstructured documents into structured data; Azure AI Search can index extracted text, metadata and vector fields.

How ranking works: Azure AI Search runs text and vector retrieval in parallel and combines them using Reciprocal Rank Fusion (RRF). Semantic ranker can then reorder the merged candidates using language understanding.

7. Metadata, Permission Filters and Ranking

A highly similar clause is still wrong if it belongs to another vendor, expired agreement, marketplace or security group.

Filter before grounding
50 candidatesKeyword + vector
→
Business filtersVendor · market · date
→
Permission filterAllowed identities/groups
→
RerankAuthority + relevance
→
Top evidence3–5 cited chunks

Recommended filter dimensions

  • Identity: vendor ID, legal entity and seller account.
  • Scope: marketplace, region, product category and service tier.
  • Time: transaction date within effective-from/effective-to.
  • Authority: executed contract over draft; signed amendment over old policy.
  • Security: user or agent is allowed to read every returned chunk.
Security rule: Do not retrieve broadly and rely on the model to ignore unauthorized passages. Enforce document-level access in the retrieval layer before content reaches the model.

Post-generation validation

  • Reject output that does not match the schema.
  • Verify every cited chunk was actually retrieved and authorized.
  • Recompute monetary rules with deterministic code.
  • Prevent the model from directly posting or paying.
  • Send low-confidence, conflicting or missing evidence to HITL.

9. Contextual Prompt Injection

Contextual guardrail meaning: Retrieved policy context may constrain what the agent can conclude, but it must never expand the agent’s permissions or redefine system instructions.

Simple retrieved-context scanner

Offline teaching example — not a replacement for a security service
import re

SUSPICIOUS = [
    r"ignore (all|any|the) previous instructions",
    r"reveal .*?(secret|password|api key)",
    r"send .*? to https?://",
    r"do not cite",
]

def screen_chunk(chunk: dict) -> dict:
    text = chunk["content"].lower()
    hits = [pattern for pattern in SUSPICIOUS if re.search(pattern, text)]
    return {
        "chunk_id": chunk["chunk_id"],
        "safe_for_grounding": not hits,
        "signals": hits,
    }

# Production: combine source governance, Microsoft Prompt Shields,
# permission filtering, tool isolation and output validation.
Regex alone is not enough. Attackers paraphrase, encode or hide instructions. Use defense in depth; assume some malicious content will pass any single detector.

End-to-end sequence

  1. Govern and ingest authoritative contract sources.
  2. Parse, chunk and enrich every clause with scope, dates and permissions.
  3. Create textual and vector index fields.
  4. Receive a validated transaction and user/agent identity.
  5. Run permission-filtered hybrid retrieval and semantic reranking.
  6. Screen the user query and retrieved content for attacks.
  7. Generate a structured, citation-backed recommendation.
  8. Verify citations and recompute monetary results deterministically.
  9. Allow only approved actions; otherwise route to finance/legal HITL.
  10. Log the evidence set, policy versions and final decision.

Offline keyword + filter baseline

offline_retrieval.py
from datetime import date

def retrieve(chunks, query, vendor_id, market, transaction_date):
    terms = set(query.lower().split())
    candidates = []
    for chunk in chunks:
        if chunk["vendor_id"] != vendor_id or chunk["marketplace"] != market:
            continue
        if not (chunk["effective_from"] <= transaction_date <= chunk["effective_to"]):
            continue
        words = set(chunk["content"].lower().split())
        keyword_score = len(terms & words)
        if keyword_score:
            candidates.append((keyword_score, chunk))
    return [chunk for _, chunk in sorted(candidates, reverse=True)[:5]]

15. Interview Questions and Answers

1. What is a retrieval-augmented agent?

An agent that retrieves external knowledge at runtime and uses the selected evidence to answer or decide, typically with citations and controls.

2. Why chunk documents?

Chunks make retrieval precise and fit relevant evidence into the model context while preserving source traceability.

3. Keyword versus vector search?

Keyword search is precise for exact terms, codes and names. Vector search finds semantic similarity across different wording.

4. What is hybrid search?

It executes keyword and vector retrieval together and merges their ranked candidates into a single result list.

5. What is RRF?

Reciprocal Rank Fusion combines multiple ranked result lists based on positions, without requiring scores from different retrieval systems to be directly comparable.

6. What does semantic ranker do?

It applies language understanding to rerank initial candidates and improve relevance of the final grounding set.

7. Why is metadata important?

It supports scope, date, authority, permission and business filters that semantic similarity alone cannot reliably enforce.

8. What is permission-aware retrieval?

It ensures the search layer returns only content the requesting identity or agent is authorized to access.

9. What is grounding?

Supplying authoritative evidence and requiring the response or decision to remain within that evidence and cite it.

10. What is indirect prompt injection?

Malicious instructions placed in third-party content that an agent later retrieves and might mistakenly follow.

11. How do Prompt Shields help?

They detect user prompt attacks and document-based indirect attacks so suspicious inputs can be blocked or handled safely.

12. Why are delimiters helpful but insufficient?

They distinguish evidence from instructions, but a model may still be influenced; detection, permissions, tool limits and validation are also required.

13. How should conflicts between documents be handled?

Apply explicit authority/version rules; if conflict remains, stop and route evidence to a qualified human reviewer.

14. Why validate citations?

Models can produce incorrect identifiers. Citation validation proves the cited chunk was retrieved, authorized and actually supports the claim.

15. Why keep financial computation deterministic?

Code provides reproducible arithmetic and policy enforcement; the model should interpret evidence, not control irreversible calculations or postings alone.
